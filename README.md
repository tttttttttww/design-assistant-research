# Design Thinking + GenAI Help-Seeking Research Platform v11.6

用于12课时设计思维课程与生成式AI学业求助研究的数据采集平台。

## v11.6 重点修复

### 1. 教师后台“学生完整记录”

后台不再只依赖“整行可点击”这种不明显的交互：

- 学生编号本身可点击；
- 每行新增“查看记录”按钮；
- 点击后先显示“正在读取12课时……”；
- 读取失败会明确显示错误并可一键重试；
- 有实际数据的课次自动展开；
- 可查看任务文字、任务作品/证据图片、AI完整对话、聊天图片、时间戳和系统事件；
- 后端改为并行读取12课时数据，减少云端存储串行等待。

同时，`admin.html`、`task.html`、`index.html` 的静态资源版本号已统一更新到 `v=11.6`，避免部署后浏览器继续使用旧缓存脚本。

> 数据存储命名空间没有改变，因此从 v11.5 升级到 v11.6 后，原先已经保存的 S01–S30 数据仍会继续被读取。

### 2. 正式数据导出精简

后台主界面日常只需要三个导出入口：

1. **AI聊天 + 聊天图片 ZIP**
   - 文件名：`AI_chat_and_images.zip`
   - 内含 `chat_messages.csv`
   - 内含 `chat_images/` 原始聊天图片
   - CSV 的 `image_zip_paths` 字段与压缩包内图片一一对应

2. **任务记录 + 学生作品 ZIP**
   - 文件名：`task_records_and_works.zip`
   - 内含 `task_records.csv`
   - 内含 `works/` 中每课上传的草图、原型、测试证据、最终作品等原图
   - CSV 的 `work_zip_paths` 字段与压缩包内图片一一对应

3. **完整正式数据 JSON**
   - 文件名：`course_research_all.json`
   - 保存完整结构，作为研究备份
   - JSON 不重复打包图片二进制本体

正式导出仍只包含 **S01–S30**，自动排除 **S00**。S00测试历史和管理员重置历史放在折叠的“测试 / 重置归档”中，平时无需下载。

旧版 `participants.csv`、`session_records.csv`、`chat_messages.csv`、`chat_attachments.csv`、`events.csv` 接口仍保留以兼容旧链接，但不再作为后台主按钮展示。

## v11.5 保留功能

- 左侧任务文字输入停止约1秒后自动保存；离开输入框再次保存。
- 打开AI、发送AI消息、上传任务图片前，先保存当前任务文字。
- “保存当前记录”按钮继续保留。
- AI聊天支持文字 + JPG/PNG/WEBP 图片，每次最多1张，≤10MB。
- 聊天图片与对应学生消息、学生编号、课次、消息序号、时间戳绑定保存。
- A/B 两组图片能力一致；组间差异只来自两只 Coze 智能体的系统提示词。
- W1–W3 自由AI；W4–W9 按 condition 路由；W10–W11 统一自由AI；W12 无AI。
- 管理员可按学生重置课次，也可批量重置当前课次；重置前自动归档。

## 自动记录的核心字段

平台记录：任务进入时间、首次打开AI时间及延迟、首次发送AI消息时间及延迟、AI打开次数、每条学生/AI消息、消息时间戳、聊天图片、任务文字字段、任务作品/证据图片、提交时间和系统事件。

注意：`first_user_message_at` 只表示“首次发送给AI”，不自动等于“首次学业求助”。正式的求助行为仍应依据后续编码规则判断。

## 教师后台

入口：`/admin.html`

建议测试顺序：

1. 用 S00 或 S01 进入学生端并填写任务文字；
2. 上传任务作品；
3. 打开AI并至少发送一轮文字；
4. 再发送一轮“文字 + 图片”；
5. 回到后台，点击该学生编号或“查看记录”；
6. 当前课次应自动展开，并显示文字、作品、完整AI对话与聊天图片；
7. 分别下载两个 ZIP，确认 CSV 和图片在同一个压缩包内且路径能对应。

## AI图片说明

聊天图片会先通过 Coze `/v1/files/upload` 获取 `file_id`，再作为多模态内容交给智能体。两只智能体应使用相同且支持视觉输入的底层模型；`COZE_ACCESS_TOKEN` 需要包含文件上传权限。
