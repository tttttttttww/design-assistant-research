## W2 明日任务：重新设计学校午餐体验
任务来源：Stanford d.school `Redesign the School Lunch Experience`。原活动让学习者通过访谈同伴理解午餐体验，再经历发现需求、定义问题、构思、反馈和迭代。本研究试用课为了保证学生获得相同信息，不做同伴访谈，改为统一的“任务学校 + 午餐体验记录”，保留核心设计过程。

### 页面已提供的完整共同资料
- 任务学校午餐时段固定30分钟；食堂场地本学期不能扩大；不同窗口排队与出餐情况不同。
- 6段统一体验记录：排队判断、到窗口才知道选择、带饭同学与排队同伴不同步、效率与选择的冲突、书包占座、工作人员窗口拥堵。
- 可改变范围：信息呈现、排队/取餐流程、座位与动线、简单可行工具。
- 明确不要求学生评价菜品口味，也不要求外部检索。

### 学生完成流程
1. 从资料中找出3个重要问题/需要，并写依据。
2. 只选一个优先问题并说明为什么。
3. 写第一版问题定义。
4. **完成第一版问题定义后，选择一个真实不确定点与普通AI讨论至少1次。**
5. 提出3个明显不同的解决方向。
6. 先作出初步选择，说明优点、风险与依据。
7. 点击“查看新反馈”，获得统一新约束：不能延长午餐时间、不能增加窗口/工作人员、不能依赖学生手机、同时要兼顾效率与选择感。
8. 决定是否修改，并形成最终方案。

新反馈在前5题完成前不会展开，避免学生一开始就用后续条件反推前面的回答。平台会记录“查看新反馈”的事件时间。

## AI使用
W2所有学生均路由到普通AI (`free`)。本节定位为**正式实验前的共同AI试用课**，不是“自然是否求助”的正式基线，因此要求每名学生在第一版问题定义后至少进行1次真实AI咨询。咨询内容由学生自己决定；之后是否继续使用、问几次均自由。平台不设置强制提交门槛，以避免AI临时故障导致学生无法交作业。

学生端右侧会显示“至少讨论1次”，普通AI仍按正常方式回答，不使用实验组的条件性学业求助支持规则。
