# v11.48 部署操作顺序：不丢旧记录

**升级前先做**：旧版登录后台 → 导出W1—W4逐课原始ZIP、每课任务CSV/聊天CSV；优先存放在两处有权限控制的位置。若旧站ZIP一直无法下载，记录管理员诊断界面的存储前缀与所有课次人数/消息数/上传数，并让部署人员先从原Blob存储侧备份，**不要为了修下载而先覆盖、切换数据库或重置环境**。

部署目标项目：保持此前站点和原Blob绑定；代码覆盖部署**不迁移、更不删除**原有`participants/`、`uploads/`、`events/`、`revisions/`等路径。继续使用相同`EXPERIMENT_RUN_ID`与`BLOB_STORE_NAME`。新版新增`participants/<id>/sessions/<week>/artifact-versions/`的追加式版本清单，以及独立`research-coding/`与`research-artifact-assessment/`研究者核实文件。

课堂操作：初稿/修改版/误传更正均通过原任务图片上传位置提交，选来源和说明（可选），可选择具体AI回复与上一课原图。AI对话随时可以自主发生，不强制每名学生发送，不强制个人回看。任务误标“完成”后先点“继续修改”（教师未锁定时），即可再上传新版本。

**功能验收不能跳过**：复制原存储绑定的测试环境（或只使用S00/S99测试）→ W5原图+修改1+修改2+更正→ 逐课ZIP下载/解压→ 检查W1/W2/W3/W4真实旧数据全部仍在；比较更新前后消息数、历史图片数、班级课次记录条数。任何不一致先停止进一步课堂使用，回滚代码配置，不覆盖Blob原件。

研究方法边界：系统实时路由标签仅用于支架投放与实施忠实度分析，不代替正式的研究者人工编码；没有对话的学生不标记为回避；学生上传新图片并自述“参考AI”不等于已证明接受了帮助；行为序列CSV仍需人工检查与去重。**没有实际导入你线上Blob时，本地程序测试不能证明你的历史数据已完整。**

未经你另外确认，不新增强制的实验组个人对话回顾教学，以免改变已经进行中的干预条件。若后续决定实施，请在实验方案和日志中单独注明干预课次和对照活动。
