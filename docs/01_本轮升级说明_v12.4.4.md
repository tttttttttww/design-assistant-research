# v12.4.4 响应式求助支架安全升级说明

## 版本基础与状态
- 基础：用户文件库中的 `design-thinking-workshop-v12.4.3-simple-prototype-iteration.zip`；源码结构与 GitHub `tttttttttww/design-assistant-research` 当前研究代码相符。本包未向 GitHub 提交、未连接/修改 Coze 云端、未部署到服务器。
- 本轮只新增**默认关闭的** V2 求助路由和 Coze 工作流搭建说明。没有修改现有 Blob key、存储路径、消息内容、学生旧记录、课次、作业结构、二组对应关系或实验/撤架日期。`SCHEMA_VERSION=25` 保持不变。
- **默认不启用**：`HELP_SEEKING_V2_MODE=off`。即使直接上传这个 ZIP，仍按原来的人设与路由机制工作；必须先配置 Coze 并验证。

## 启用开关
| 环境变量 | 功能 |
|---|---|
| `HELP_SEEKING_V2_MODE=off` 或留空 | 原版路由，正式学生没有新支架，默认值 |
| `HELP_SEEKING_V2_MODE=test` | 仅测试号 S00 的支持型会话启用 V2，正式学生不变；S99仍用于普通AI对照测试 |
| `HELP_SEEKING_V2_MODE=on` | 所有今后实际匹配支持型AI的求助会话启用 V2；需课前明确批准并登记首次启用课次 |

**操作顺序**：① 保留完整旧 ZIP 和服务器导出备份 → ② 核对当前正式学生原始记录存在 → ③ 在 Coze 测试/备份支持型机器人上完成工作流 → ④ 启用 `test`，用 S00 做不同情境、图片、两轮调整测试 → ⑤ 检查后台消息与现有 Blob 导出不变、问答标记被去除 → ⑥ 研究者确认后才切到 `on`，记录日期、课次及机器人发布版。若 Coze 仍用旧提示词而没有V2标记，平台继续兼容旧标记并如实标注历史版本，**不能假装新工作流生效**。

## 数据与研究风险
1. 工作流系统分类不是学生真实策略的正式研究编码。需两名研究者对真实对话进行独立人工编码；同一 student-message / AI-reply pair 用 `interaction_id` 对齐。
2. 如果新规则仅在后期使用，不可声称整个 W3—W10 均以该工作流进行干预。干预保真度按实际版本和课次分段。
3. **特别核对历史分组**：当前源码 W4、W5 的条件映射为 A=支持型、B=普通；W6—W10 映射为 A=普通、B=支持型；W14/W15 代码项也存在，但与 W11—W13 顺序不一致。不要据配置推断每个学生实际接触条件；务必以学生记录的 `condition_at_time`、`ai_variant`、消息时间、老师当时的发布日志逐一核验。
4. 现有代码还有部分阶段对话轮数门槛（原测试显示W7 9/10轮提交限制）。如果将“求助频率”作为自然发生性指标，须剔除或单独标记被课次规则强迫的消息。
5. 未增加 `rrweb`/眼动/屏幕回放。未改原数据库。若后续决定采集屏幕记录，需单独审批未成年人隐私处理方案。
6. `node_modules` 不在 ZIP 内；部署端仍按现有项目流程安装依赖。本包运行项目内的 `npm test`，并已通过当前静态/模拟测试，尚未在正式服务器或Coze API联调。
